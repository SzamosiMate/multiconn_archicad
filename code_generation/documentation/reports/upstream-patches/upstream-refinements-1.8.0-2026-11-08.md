# Align Tapir Part 5 schema names with existing client types

Compared the patched MultiConn Tapir 1.8.0 schema and its generated public types with the 124 definitions added by [Tapir #2390](https://github.com/ENZYME-APD/tapir-archicad-automation/pull/2390). The fork's `main` was initially synced to upstream `634e5a46cc4522dcf0750f1e4e57745ada86e07a`. Published the revised proposal [ba0e0dba](https://github.com/SzamosiMate/tapir-archicad-automation/commit/ba0e0dbadcac6bbecf83fb65d6911a7e219449de) on `schema/refinements-1.8.0-part5-names`, based on upstream `8bcf7dc362df0b1b19dd48f22d4e198c613c827d`.

- Renamed 29 definitions using command schema locations and expanded shapes. Two MEP creation payloads take the established `MEPElementData` and `MEPRoutingElementData` names while preserving fields added since Tapir 1.8.0. Retained ten clearer #2390 names for Favorites, IFC classification reference updates, and library inventory or updates. MultiConn can preserve imports for those names through downstream aliases when it adopts the released schemas. See the user's [naming rationale in #2379](https://github.com/ENZYME-APD/tapir-archicad-automation/issues/2379#issuecomment-6724468082).
- Consolidated the MEP preference table ID and domain duplicates and kept their descriptions at their original uses. Adopted the shared `MEPElbowParameters` and update reference from [#1754](https://github.com/ENZYME-APD/tapir-archicad-automation/pull/1754). The definition says “Elbow parameters. Archicad 29 or newer.” The `ElementMEPRoutingParameters.properties.elbowParameters` reference retains “The elbow parameters of a routing node (RoutingNode::Modifier::SetElbowDefaultParameters). Archicad 29 or newer.” This drops the extra update-only `preferenceTableId` annotation from #2390 and preserves its validation contract.
- Restored `LibraryPartCreationDetails` for the plural creation response. The metadata read response and readable script selector now have distinct names. The unchanged metadata update body, writable script body and deletion enum get their established names `LibraryPartMetadata`, `LibraryPartScripts` and `LibraryPartScriptType`.

Tapir's generated and expanded schemas matched for all 789 commands and all 982 original definitions under the name mapping, allowing only the elbow field annotation difference. All references resolve. The docs renderer kept the setter description at the update use. Tapir's example coverage check passed for 788 registered commands on the revised branch. This was source-schema validation, with no SDK build or live Archicad test. The [active queue](../../schema-patch-tracking.md) still governs downstream adoption once the changes appear in released documentation.
